一、什么是DNS泄露？为什么它如此致命？

DNS（域名系统）是互联网的“电话簿”，负责将域名转换为IP地址。通常情况下，当您开启代理时，所有流量（包括DNS查询请求）应当通过加密隧道发送至海外代理服务器，由远端服务器代为解析。

然而，如果代理客户端配置不当或系统默认优先使用了运营商本地DNS（例如中国电信/联通/移动的DNS），那么您的计算机在访问海外网站之前，就会先向本地运营商发出明文查询。此时：

  • 真实位置曝光： 目标网站虽然收到来自海外节点的HTTP请求，但通过WebRTC或内嵌探测脚本发现您的DNS服务器归属地在中国大陆，直接触发地域阻断机制。
  • 隐私轨迹暴露： 本地运营商能够清晰记录您所查询的每一个海外域名，代理加密失去了隐私保护的本质意义。
  • 中间人污染与劫持： 运营商DNS劫持可能返回虚假IP，直接导致海外网站打不开或连接重置。

二、如何检测自己是否存在DNS泄露？

在着手机场DNS泄露解决前，我们先通过标准工具进行测试验证：

  1. 打开全局/规则代理模式，连接至 吹雪云 的海外节点（如日本或新加坡）。
  2. 访问国际知名的权威检测站点：https://www.dnsleaktest.com 或 https://ipleak.net。
  3. 点击 Standard Test 或 Extended Test。
  4. 判定标准： 观察测试结果中的“IP”和“Country”。如果列表中出现了 China (CN) 或您本地宽带运营商的名称（如 China Telecom），说明存在严重DNS泄露；如果列表全部为海外节点所属服务商（如 Cloudflare、Google 或本地节点机房），则表明DNS防护完好。

三、主流客户端彻底解决DNS泄露实操指南

1. Clash Verge Rev / Clash Meta (Mihomo) 防泄露设置

Clash Meta 内核提供了极其强大的 DNS 分流与 Fake-IP 机制。解决DNS泄露的最佳配置方案如下：

  • 开启 TUN 模式： TUN模式能够接管整机虚拟网卡层面的所有流量，杜绝操作系统本地旁路绕过代理直接发起DNS查询。
  • 配置 Strict-Route 与 DNS 劫持： 在设置中开启 严格路由 (strict-route: true)，确保所有DNS请求无一漏网。
  • 合理配置 Nameserver Policy： 将国内域名交由 223.5.5.5 等快速解析，将所有未匹配流量或海外域名强制分配至 https://1.1.1.1/dns-query (DoH) 或代理隧道远端解析。

2. Sing-box 客户端防泄露配置

Sing-box 作为新一代轻量级代理核心，在处理DNS方面尤为严密：

  • 在 dns 模块中，配置独立的 remote DNS（例如 tls://8.8.8.8），并将其 detour 指定到代理出口 proxy。
  • 在 route.rules 中配置：针对海外规则集的 DNS 解析强制路由至 remote DNS，阻断任何回退到直连局域网的可能。

3. iOS 端 Shadowrocket / Loon 设置

在 iPhone 或 iPad 上使用 多设备使用机场 时：

  • 进入 Shadowrocket 设置 -> DNS，将 DNS 覆盖启用。
  • 添加安全 DNS 服务（如 https://dns.google/dns-query 或 Cloudflare DoH）。
  • 开启 TUN 隔离 与 始终开启后备 DNS 选项。
